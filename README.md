# hermes-skills-lib — библиотека доменных скиллов + установщик системы

Здесь живут два разных предмета:

1. **Библиотека доменных скиллов** — вынесенные из `~/.hermes/skills` доменные
   скиллы: `skills/<категория>/<имя>/SKILL.md` (+ supporting files). Оркестраторы
   в `~/.hermes/skills` ссылаются на этот каталог абсолютными путями.
   Категории: network/, hermes/, osint/, github/, academic/, construction/ и др.
2. **install-skills.sh** — установщик рабочей системы Hermes из единого зеркала.

## Установка системы на новой машине

Источник — **приватный** репозиторий `AllexandrKnife/hermes-system-mirror`:
он содержит всю систему (SOUL.md, config.yaml, memories, mem_lib.md, скиллы,
библиотеки, планы, скрипты, plugins, cron/jobs.json) и рабочие каталоги.

Скрипт лежит в этом репозитории (публичный → скачивается без токена; токен нужен
только для доступа к приватному зеркалу):

```bash
curl -fsSL https://raw.githubusercontent.com/AllexandrKnife/hermes-skills-lib/main/install-skills.sh | bash
```

Токен (нужен из-за приватности зеркала) берётся по приоритету: `GITHUB_TOKEN` →
`~/.git-credentials` → интерактивный ввод с `/dev/tty` (при `curl | bash` ввод
идёт с терминала, а не из пайпа). Без интерактива:

```bash
curl -fsSL .../install-skills.sh | GITHUB_TOKEN=<токен> bash
```

## Что раскладывает скрипт

| В зеркале | Куда ставится (root-режим) |
|---|---|
| `hermes/SOUL.md`, `config.yaml`, `mem_lib.md` | `/root/.hermes/` |
| `hermes/memories/*` | `/root/.hermes/memories/` |
| `hermes/skills/*` | `/root/.hermes/skills/` |
| `hermes/scripts/*`, `plugins/*`, `plans/*` | `/root/.hermes/…` |
| `hermes/patches/*` | `/root/.hermes/patches/` |
| `hermes/cron/jobs.json` | `/root/.hermes/cron/jobs.json` |
| `hermes-skills-lib/*`, `hermes-triz-core/*` | `/root/…` |
| `plans/*`, `scripts/*` | `/root/plans`, `/root/scripts` |
| `служебные-инфраструктура/`, `skills-migration/` | `/root/…` |
| `memory/*` | `/root/memory/` |
| `данные/*` | `/root/<имя каталога>` — **только с `--with-data`** |
| `проекты/*` | `/root/<имя каталога>` — **только с `--with-data`** |

Ключи:
- `--base-dir DIR` — префикс путей установки (песочница/тест), система не трогается;
- `--dry-run` — показать, что будет установлено, ничего не записывая;
- `--with-data` — развернуть также `данные/` и `проекты/`. Без флага данные не
  ставятся, и скиллы, ссылающиеся на `/root/Отчёты`, `/root/sbbp-case` и т.п.,
  на новой машине не найдут эти каталоги. Совпадающие по имени файлы
  перезаписываются, чужое не удаляется.

## Режимы

- **root** (`id -u == 0`): база `/root` — пути в скиллах совпадают, правка не нужна.
- **user**: база `$HOME`. После раскладки скрипт переписывает `/root/…` → `$HOME/…`
  во всех текстовых файлах скиллов, библиотек, планов, скриптов и `memory/`
  (grep -Z + xargs -0, пути с пробелами и кириллицей сохраняются). В конце печатает
  число оставшихся ссылок `/root/`.

Идемпотентность: повторный запуск обновляет зеркало (`git pull`) и перекладывает
файлы; кэш зеркала живёт в `<base>/.hermes-mirror`. Токен в `.git/config` не
остаётся — origin всегда переставляется каноническим URL.

## Секреты

Зеркало содержит ЖИВЫЕ ключи (config.yaml, отдельные скиллы). Поэтому:
- репозиторий зеркала обязан быть приватным — скрипт проверяет это перед
  установкой и останавливается, если он публичный;
- не публикуйте содержимое зеркала и не переносите его в публичные репо.

## Проверка после установки

1. В отчёте скрипта — счётчики: скиллы, библиотека, ТРИЗ-ядро, планы, память;
   с `--with-data` дополнительно строка о ключевых каталогах данных.
2. Сверка ключевых файлов с рабочими: `cmp <base>/.hermes/SOUL.md /root/.hermes/SOUL.md`.
3. `--dry-run` + `--base-dir /tmp/…` — безопасная проверка раскладки.
