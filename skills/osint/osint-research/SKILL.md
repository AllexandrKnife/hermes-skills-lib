# OSINT-аналитическое исследование

## Когда использовать
- Пользователь просит «исследовать», «разобрать ситуацию», «OSINT», «аналитическую записку»
- Нужен сбор данных из открытых источников (СМИ, аналитика)
- Формат результата — структурированный документ

## Предварительные уточнения
Одним блоком уточнить, если не задано: период, глубина источников (русские/англо/оба), фокус, формат (доклад/записка), региональный разрез.

## Сбор данных (без web_search)
- `mcp__ruflo__http_fetch` — прямой запрос к новостным сайтам (Interfax, Vedomosti, RBC, Reuters)
- `terminal` + `curl` — поиск через DuckDuckGo lite
- Данные искать в `<title>`, `<meta name="description">`, `<meta name="keywords">`, `<script type="application/ld+json">` — SPA-сайты отдают JS-болванку
- Классические сайты (Интерфакс) — полный HTML, самые информативные для поиска
- Из результатов поиска: даты заголовков дают хронологию

## Структура записки
Хронология → Текущее состояние (по регионам/сферам) → Причины → Тенденции и прогноз → Социальные последствия → Источники

## Количественное моделирование (метод «бассейна с двумя трубами»)

### Когда строить модель
- В данных есть явный supply/demand дисбаланс (производство vs потребление)
- Есть третий независимый прогноз, который надо верифицировать
- Можно выделить ключевую переменную (темп атак, скорость ремонта) и пощупать сценарии

### Методология
Модель: `d(запасы)/dt = производство(t) − потребление(t) − экспорт(t)`

Где:
- **Производство(t)** — базовый объём × (1 − потери от атак + восстановление) + сезонность
- **Потребление(t)** — базовый спрос × сезонность × (1 − demand destruction). Demand destruction = нормирование, ограничения, QR-коды — спрос не исчезает, но его реализованная часть падает
- **Экспорт(t)** — функция сценария (до ступеньки запрета)
- **Запасы(t)** — интегрируемая переменная-индикатор: когда падает ниже N дней потребления → коллапс

### Процесс
1. Собрать верифицированные точки: Росстат, ЦБ, Минэнерго — это калибровочные якоря
2. Задать допущения прозрачно — каждое в отдельный пункт
3. Построить на Python (numpy + matplotlib) — запас ~20 мин
4. Три графика: производство/спрос, запасы, дефицит+цены
5. Сценарии: 3-4 варианта — мера по отдельности, меры вместе, worst/best case

### Сравнение с чужими прогнозами
- Если прогноз расходится — найти какое именно допущение даёт разницу (блогер не учёл demand destruction → коллапс на месяц раньше)
- Расхождение в цифрах, совпадение в тренде — это нормально

## Верификация сторонних прогнозов и факт-чекинг
- Когда пользователь скидывает анализ блогера/телеграм-канала — не отмахиваться, а разобрать:
  - Какие данные он использует (можно проверить?)
  - Какие допущения (реалистичны?)
  - Какие факторы упущены (чаще всего — demand destruction, log lag, скрытые запасы)
- После верификации: «вот где он прав, вот где не учёл, вот как выглядит полная картина»
