# Аудит ведомостей ВИР/ВВР по ТЦП

ВИР (ведомость исполнения работ) и ВВР (ведомость выполненных работ) — приложения к допсоглашениям/договорам на строительство/модернизацию БС. Сверка с ТЦП (тарифно-ценовые показатели подрядчика) выявляет двойную оплату, необоснованные коэффициенты и арифметические ошибки.

## Как использовать

```bash
python3 ~/.hermes/skills/productivity/tcp-vedomost-audit/scripts/check_vir.py "<ведомость.xlsx>" [--verbose]
```

Скрипт сам находит лист с заголовками «№ п. по ТЦП» / «Наименование», маппит колонки, распознаёт строки итога. Проверяет 4 вещи:
1. **Несовместимые пары** (XOR) и запреты разделов — обе позиции в одной смете = двойная оплата.
2. **Арифметику**: Кол-во × Цена × Коэф = Стоимость по каждой позиции.
3. **Сумму позиций = Итого** в ведомости.
4. **НДС = 22%** от суммы (сверять со ставкой документа).
5. **Коэффициенты** — сверка с известными значениями ТЦП (словари KNOWN_COEFFS / CONDITIONAL_COEFFS внутри скрипта).

Справочник цен и правил ТЦП 2621: скилл `tcp-2621` (references/tcp-2621-prices.md, tcp-2621-rules.md).

## Питфоллы (3 итерации отладки на реальной ведомости)

1. **«аналогичную» содержит подстроку «налог»**. Фильтр строк итога по `'налог' in text` ложно срабатывает на наименовании 3.7.4 («...панели распределения питания (DCDU) или **аналогичную**») — позиция молча теряется. Фильтр итога — ТОЛЬКО точными маркерами: `'итого без ндс'`, `'налог на добавленную'`, `'итого с ндс'`. Одиночные подстроки «налог»/«ндс» не использовать.

2. **Демонтажные модификаторы «X/9.1»** (напр. «3.7.4/ 9.1»): итоговый коэффициент = ПРОИЗВЕДЕНИЕ коэффициентов. Пример: 3.7.4 (монтаж АФУ со скидкой 0,75) × 9.1 (демонтаж 0,75) = 0,5625 — корректно, НЕ ошибка. Сверять 9.x по формуле base_coef × expected, а не как одиночный коэффициент.

3. **Условные коэффициенты** (CONDITIONAL_COEFFS): 3.11/3.12 = 1,5 только для СДВОЕННЫХ комбайнеров/МШУ; для одинарных 1,0 — не ошибка, проверять по факту. 3.7.4 = 0,75 только при подключении к существующим антеннам (без установки новых); если антенны новые — 1,0, переплата = 25% от позиции. **Как проверить условие: читать ОТР (pdf) через PyMuPDF** — спецификация АФУ помечает антенны «сущ.» (T1002S6R012) vs «проект.» (T1004S6R023, новые). По переписке/ИД-Excel не определять — подрядчик трактует расширительно. Проверено: в 5 ДС 08.2026 к=0,75 обоснован на 4 станциях (антенны сущ.), на 55434 к=1,0 (новые) — прежний риск 20 801,25 закрыт. Такие случаи помечаются «проверить условие», а не «ошибка».

4. **Строки без номера ТЦП** (заголовки «Работы на БС: …») — не позиции. Позиция = строка с номером пункта по regex `^\d+(\.\d+)*$`. Номера с демонтажем: «3.7.4/ 9.1» → пункты ['3.7.4', '9.1'].

5. **Ведомость может быть на нескольких листах** — обрабатываются все листы с заголовками.

## Реальные находки (паттерны завышения)

- **19.3.19 (монтаж SFP) ↔ раздел 3.7 (монтаж АФУ)**: частая пара в ведомостях модернизации БС. SFP-монтаж запрещён совместно с 3.7/3.18/3.19/18.1/3.6 — 12 987 ₽ на 9 шт. Полное примечание 19.3.19 (дословно, для цитирования): «Применимо для БС. Не применимо совместно с пунктами разделов 3.7; 3.18; 3.19; раздел 18.1, 3.6.1.-3.6.19; 3.7.1.-3.7.28». Механика: в раздел 3.7 уже включены прокладка/подключение оптики (гофрорукав и оптический кабель — в стоимости пункта), SFP — оконечник того же тракта → 3.7.4 + 19.3.19 = двойная оплата. **Вариант записи «19.3.19/9.1.1» (демонтаж/монтаж, к=1,5 = перенос) запрет НЕ обходит** — базовая работа та же 19.3.19, примечание привязано к пункту.
- **ВАЖНО (аргументация, уточнено пользователем 08.2026)**: аргумент «ТЦП запрещает» — СЛАБЫЙ для спора с подрядчиком. ТЦП — внутренний справочник цен Заказчика; раз ДС+ВИР подписаны, Заказчик сам разрешил позицию вопреки своему ТЦП, а подрядчик по внутренним правилам Заказчика не обязан ходить. Юрист это разобьёт. **Сильный аргумент по SFP: позиции НЕТ В ПРОЕКТЕ (ОТР)** — проверить спецификацию ОТР через PyMuPDF: SFP = 0 упоминаний в ОТР 57469 и 53565 (только RRU, фильтры, комбайнеры, кабели). Значит модули не заказывались, не выдавались подрядчику со склада, монтировать было нечего → бремя доказывания на подрядчике: пусть покажет фотоотчёт/акты/накладные на получение модулей (ст. 711 ГК РФ — платят за выполненное). Косвенное доказательство: число SFP «плавает» между версиями (ВВР_1: 9 шт → Доп_2: 6 шт) — если бы монтировал по проекту, знал бы точное число из чертежа; плавающее число = взято с потолка. ТЦП-аргумент — только как дополнение, не основа.
- **Проверять оба документа сделки**: Доп_N (ВИР) и ВВР_N — несовместимость тиражируется; если пара в обоих, это системное завышение, а не опечатка. НО при проверке ВИР ВВР не смешивать (см. Юридическая рамка).
- Другие пары: 1.31↔1.35, 1.37↔1.40, 2.21↔2.24, 2.22↔2.25, 2.51↔2.48/2.49, 3.1.13↔3.1.1, 3.16↔3.10, 20.1↔1.39 (полный список — в скилле tcp-2621).

## Модернизация БС — избыточные позиции (решение ЦЭСС, 07.2026)

При аудите ДС на модернизацию БС проверять «по умолчанию» включённые позиции:
- **Марка ЭС (1.33.10, ~5 947,50 ₽ с к=0,75)** — не включается в первичные ДС на модернизацию (решение ЦЭСС, Митрофанов; Павлов; контроль Калягинов). Электроснабжение при модернизации не меняется, альбом ЭС уже выпущен при строительстве.
- **ПНР (4.2–4.8)** — только на вновь вводимые диапазоны. ПНР на диапазоны, работавшие до модернизации — избыточны. Новая редакция ТЦП (после 22.07.2026): один п.4.1.1 на весь сайт, 4.2–4.8 исключить; при замене платы/RRU/RRH/RFM — ПНР к=0,75 на диапазон из ИД; софтовые работы без монтажа — ПНР не оплачивается; рефарминг (диапазон делится на 2, меньший не выключается) — второй с к=0,75. Применяется к ДС, заключённым ПОСЛЕ уведомления (п.1.2 договора); старые ДС — по ТЦП 18.1.
- **SFP (19.3.19)** — количество по проектной схеме, не шаблонное «9 шт».
- Кейс: ДС DMC240_519266_288_57469 (БС 57469 Тлт-8) — избыток 61 487,50 ₽ (23,7%), после добавления пары 19.3.19↔3.7.4 — 74 474,50 ₽ (28,7%); масштаб ущерба = кол-во ДС на модернизацию × сумму избытка (не × число БС — на одной БС несколько модернизаций/ДС). Детали: references/case-57469.md

## Оценка риска (быстрая прикидка)

Переплата по паре = стоимость «лишней» позиции (дубль) или разница между оплаченным и фактически исполненным вариантом (подмена: 2.24 вместо 2.21 = +4 800 ₽/м² × площадь). По одной БС суммарный риск по всем несовместимостям ~180–230 тыс. ₽ без НДС; при масштабе сети — десятки млн ₽/год.

## Формат вывода

Скрипт печатает: блок «НЕСОВМЕСТИМОСТИ» (тип, пункты, строки), «Арифметика» (позиции или сводка ошибок), «Итог» (сумма, расхождение с ведомостью, НДС), «Коэффициенты» (расхождения и «проверить условие»). Exit code 0 = чисто, 2 = найдены проблемы. Ошибки-кандидаты на переплату суммируются в выводе.

## Юридическая рамка: ВИР = ТЗ (не спорить с этим), спорить об ИСПОЛНЕНИИ

Ключевой аргумент юриста (Тарасов, 08.2026, уточнено пользователем):

- **ВИР подписан сторонами = ТЗ подрядчику** (поручение «сделай марку ЭС»). Мы сами включили работу в задание и подписали. Подрядчик её исполнил и потребовал оплату. «Раз сами поручили и он исполнил — обязаны оплатить. Оспаривать собственное поручение нельзя».
- **НЕ спорить с юристом на уровне «ВИР — просто бумажка / просто смета»** — это проигрышный ход, юрист разобьёт его за один вопрос. Тезис «ВИР = ТЗ» принимается целиком.
- Спор переносится на уровень ФАКТА: **исполнена ли работа надлежаще**. «Исполнил» = выдал результат, соответствующий ТЗ и ОТТ (марка ЭС = альбом с электротехническими расчётами, ОТТ БС п.2.3.10.3). Пустой альбом результатом не является → оплата за результат, а не за бумажку (ст. 711 ГК РФ). Бремя доказывания выполнения — на подрядчике (ст. 753 ГК РФ).
- **Выигрышная формулировка позиции**: НЕ «не платим» (проигрывает), а **«платим за НАДЛЕЖАЩЕЕ исполнение — предъявите результат»** (альбом с расчётами по каждой станции / накладные / фото / ИД). Против «платите, мы исполнили» один вопрос: «предъявите исполнение».
- Выход даёт сам юрист: «можем отказаться, если работы выполнены НЕКАЧЕСТВЕННО» → ст. 723 ГК РФ (соразмерное уменьшение цены) либо требование надлежащего исполнения («сделайте альбом с расчётами — тогда и поговорим»).

Роли документов (НЕ смешивать):
- **ВИР (ведомость исполнения работ) — входит в состав ДС** (смета/поручение). При проверке несовместимостей обрабатываются ТОЛЬКО ВИР из ДС.
- **ВВР (ведомость выполненных работ) — отдельный приёмочный документ**, не входит в ДС. К проверке ВИР присоединять НЕЛЬЗЯ (пользователь: «вир может находиться только в дс или отдельно — зачем ты ввр присоединил»). ВВР уместен в описании спора/повестки (история отклонения, предмет ВКС «что закрываем»), но не в перечне несовместимостей ВИР.

Практические рычаги по стадиям:
1. **ВВР НЕ подписан** (основная рабочая стадия): не подписывать, пока в ведомости избыточные позиции (марка ЭС, SFP, ПНР на существующие диапазоны). Козырь — письменное признание подрядчика в переписке («альбомы ЭС пустые, ошибочно выпустили, электрику не трогали» — Филимонов, 31.07.2026): это доказательство невыполнения, и подрядчик не сможет оспорить, если сам это написал с копией ЦЭСС. Признание по ДРУГИМ объектам — подкрепление, а не основа (юрист подрядчика это скажет).
2. **ВВР уже подписан**: путь только через качество — ст. 723 ГК РФ (соразмерное уменьшение цены за ненадлежащее качество, напр. альбом ЭС без электротехнических расчётов = несоответствие ОТТ БС п.2.3.10.3, подтверждается тех. экспертом) или ст. 1102 ГК РФ (неосновательное обогащение).
3. Стратегия на совещании: добиваться фиксации в протоколе исключения избыточных позиций ДО подписания ВВР. После подписания — поздно, юрист прав.
4. **Если ДС перевыпускался (Доп_1 → Доп_2)** — составы позиций и суммы могут отличаться (SFP 9→6 шт, ПНР 4.3/4.5 → 4.7/4.7.1). Первый вопрос повестки: «какой документ закрываем» — от этого зависят все суммы спора.

## Позиция СББП к ВКС (структура документа)

Готовый каркас позиции на совещание по закрытию объёмов (папка кейса, `Позиция_СББП_<тема>_<дата>.txt`):
1. Контекст ВКС: инициатор, формат (протокол), повестка, список объектов, сумма ДС без НДС.
2. Подтверждённая избыточность: позиции, суммы, ОСНОВАНИЕ для каждой (решение ЦЭСС / примечание ТЦП / признание подрядчика / факт невыполнения по ОТР).
3. Спорная зона: предмет, позиции сторон (подрядчик / стройка / техблок), чей аргумент сильнее и почему (по ОТР/ИД).
4. Что проверено и закрыто (снятые риски) — снимает прежние «проверить условие» из аудита.
5. Чек-лист наблюдателя: что фиксировать в протоколе, кто ответственный, какие прецеденты (решение по одной БС = ответ для всех аналогичных).
6. Цифры для протокола: подтверждённая сумма, спорная сумма, общая сумма, формула масштаба.

Сопутствующие правила: если участник от СББП — наблюдатель, готовится чек-лист наблюдения, а не линия защиты; «простыми словами» — отдельная шпаргалка-файл рядом с формальной позицией.

## Формат документов для пользователя (предпочтения Колчина)

- **Номера БС всегда с названиями**: «57469 Тлт-8 квартал», «53565 Тлт-База оборудования» — пользователю так легче ориентироваться. Словарь номер→название подставлять везде в тексте, не только в шапке.
- **По запросу «простыми словами» — отдельный файл-шпаргалка**: тот же разбор, но человеческим языком (аналогии: «SFP — флешка для оптики», «ПНР — оживить оборудование»), без канцелярита, с блоком «что смотреть на совещании» и «цифры на память». Формальный файл при этом сохраняется — шпаргалка его не заменяет.
- Итоговый файл позиции/разбора кладётся в папку кейса (рядом с исходными ДС/перепиской), имя `Позиция_СББП_<тема>_<дата>.txt`.

## Scope & Limits

Скрипт заточен под формат ведомостей DMC ВымпелКом (лист «ВИР 1»/«ВВР», колонки B=№ТЦП, C=наименование, D=ед., E=кол-во, F=цена, G=коэф, H=стоимость). Цены и правила — из конкретного ТЦП (см. tcp-2621); при другом подрядчике обновить словари коэффициентов и пар.
