# Принудительная загрузка скилов (preload) в Hermes

## Задача

Скилл должен загружаться в КАЖДУЮ интерактивную сессию автоматически — без ручного `-s` и без
вероятностного решения модели (когда триггер скилла «проскочил» при сканировании описаний).

## Механизм (проверено по исходникам, реальный инстанс)

- Флаг `hermes -s <skill>` — разовая загрузка. Технически это установка env-переменной
  `HERMES_TUI_SKILLS` для TUI-процесса (hermes_cli/main.py:2359).
- Дефолтный интерфейс `hermes` — TUI (main.py:304, TTY-gate).
- tui_gateway/server.py:6194 читает `HERMES_TUI_SKILLS` при старте КАЖДОЙ сессии →
  build_preloaded_skills_prompt (agent/skill_commands.py:747) инжектит полный SKILL.md
  в системный промпт с пометкой «preloaded — active guidance for this session».
- `~/.hermes/.env` грузится в окружение ДО спавна TUI (main.py:697 load_hermes_dotenv) →
  переменная из .env переживает спавн и работает как постоянный прелоад.

## Как сделать постоянным

Добавить в конец `~/.hermes/.env`:

    HERMES_TUI_SKILLS=document-critic

Несколько скилов — через запятую. Действует со следующего запуска `hermes`.
Альтернатива для интерактивных сессий — shell-алиас: `alias hermes='hermes -s document-critic'`
(в ~/.bashrc). Эффект тот же.

## Ограничения

- Только интерактивные TUI-сессии. Gateway-платформы (Telegram, Discord и т.д.) `HERMES_TUI_SKILLS`
  не читают — для них другой механизм (per-platform конфиг).
- Прямой путь cli.py (без TUI) читает только флаг `-s`, не env-переменную.
- Прелоад уважает `skills.disabled`: скилл, отключённый через конфиг, не загрузится
  (вернётся в missing, без ошибки).
- `.env` — защищённый файл: write_file/patch блокируются. Append через terminal МОЖЕТ быть
  отклонён пользователем (реальный прецедент 08.2026) — давать однострочник для ручного ввода,
  не пытаться записать самому и не повторять после отказа.

## Проверка после установки

Запустить `hermes` — в стартовой строке сессии появится список прелоаженных скилов
(cli.py:15000 `_startup_skills_line_shown`), содержимое скилла присутствует в контексте.
Проверка через `grep "^HERMES_TUI_SKILLS=" ~/.hermes/.env`.

## Почему это не «просто поправить триггер скилла»

Авто-загрузка скилла по описанию — вероятностная (модель сканирует описания и решает).
Триггер в SKILL.md повышает шанс, но не гарантирует. Прелоад через HERMES_TUI_SKILLS —
детерминированный: скилл попадает в системный промпт до первого хода модели.
Комбинация «сильный триггер в описании + прелоад» — надёжный паттерн для критичных скиллов.

## Pitfall: YAML frontmatter при патче скилла

`skill_manage(action='patch')` по полю `description` во фронтматтере отклоняет правку с
ошибкой «mapping values are not allowed here», если в тексте есть двоеточие+пробел
(«выдачей: арифметика») — YAML читает его как вложенный mapping. Решение: формулировать
без `: ` (тире, запятые) или брать значение description в кавычки. Касается и новых
описаний при `create`, и правок существующих скиллов.
