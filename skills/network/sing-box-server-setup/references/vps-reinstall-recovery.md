# Восстановление ноды после переустановки ОС (кейс vdska 5.39.255.242, 2026-08-07)

## Контекст
Переустановка ОС = потеря серверных приватных ключей. Клиентские артефакты
(инстанс-файлы, WSL-конфиги, keenetic-awg0.conf) переживают переустановку.

## Что сохраняется 1-в-1 (собрано до переустановки)
- UUID 26bc3168-fbde-41e3-9d04-16535a4f304d (единый на все протоколы)
- Порты: VLESS-Reality TCP 443 (перенесён с 22524), Hysteria2 UDP 42954,
  TUIC UDP 60240, Anytls TCP 56799, доп. TCP 2082
- sni: apple.com (VLESS), www.bing.com (hy2/tuic/anytls), fp chrome,
  flow xtls-rprx-vision, sid f60204fc
- AWG: порт 51871, сеть 10.7.0.0/24, MTU 1420, Jc=5 Jmin=30 Jmax=50 S1=16 S2=16,
  H1-H4, PSK mNANbVQE... — всё из /root/keenetic-awg0.conf (клиентский конфиг WSL)

## Что теряется при переустановке
- Приватный ключ Reality x25519 — жил только в /etc/s-box/sb.json на сервере.
  pbk в клиентском конфиге = публичная часть, пара не восстанавливается.
  → сгенерировать новый ключ, обновить pbk в /etc/sing-box/config-vdska.json и ссылках
- Приватный ключ AWG-сервера — жил только в /etc/amnezia/amneziawg/awg0.conf.
  PSK и Jc..H4 НЕ теряются (они в клиентском конфиге).
  → новый ключ, обновить PublicKey в конфиге Keenetic (переимпорт через RCI)

## Порядок восстановления
1. Переустановка ОС — только юзер, панель хостера (клон-агент не может)
2. apt update/upgrade + apt-get install -y iproute2 (без него awg-quick падает)
3. sing-box: sb.sh (русская версия с 45.134.15.185, процедура в SKILL.md) →
   правка /etc/s-box/sb.json под сохранённые UUID/порты/sni/sid → новый reality-ключ
4. AWG: сборка модуля v1.0 (патч compat.h для ядра 5.15) → awg0.conf
   с сохранёнными Jc..H4/PSK/портом → новый серверный ключ
5. Клиенты: config-vdska.json (новый pbk), Keenetic (новый PublicKey сервера)
6. Verify: systemctl is-active sing-box, awg show awg0, curl через 127.0.0.1:1082
   → egress IP 5.39.255.242

## ДИАГНОСТИКА «AWG не поднимается после переустановки» — КЛЮЧЕВЫЕ УРОКИ
1. Симптом «Keenetic tx растёт, сервер rx=0, handshake нет» = пакеты НЕ доходят
   до сервера, это НЕ конфиг. Проверка: tcpdump -i ens18 udp port <порт> на сервере.
2. Проверять путь с НЕСКОЛЬКИХ точек: с другого VPS (ssh 45.134.15.185 →
   /dev/udp на тестовый порт) и с домашнего пути. Сравнение локализует фильтр.
3. ВАЖНО: WSL/Windows могут ходить через туннель (eurodir 46.30.47.120 и т.п.) —
   «домашние» тесты с WSL НЕ валидны как тесты домашнего IP! Проверять source
   в tcpdump: если видишь IP другого VPS — трафик идёт через туннель.
4. Чистая проба с домашнего пути: PowerShell на Windows-хосте (UdpClient.Send
   на IP:порт), source в tcpdump покажет реальный CGNAT/публичный IP.
5. Фильтр хостера может блокировать: (а) конкретный порт целиком (51871 даже с
   датацентров), (б) CGNAT-диапазон клиента (100.64.x.x — пакеты с дома не доходят,
   с датацентров проходят). Решение — сменить порт на проверенно открытый и
   дописать тикет хостеру (анти-DDoS). 07.08.2026: 50000 проходит с датацентров,
   с домашнего CGNAT — нет, Keenetic ждёт открытия UDP хостером.

## Выбор ОС при переустановке
- Ubuntu 22.04 LTS minimal — лучший: sb.sh завязан на apt (DEBIAN_FRONTEND/needrestart),
  AWG-патч проверен на ядре 5.15, поддержка до 04.2027
- Debian 12 — запасной: apt есть, но AWG-сборка на ядре 6.1 — непроверенный путь
- CentOS/RHEL — нет: dnf, sb.sh не рассчитан, CentOS 7 EOL 06.2024
- Ubuntu 24.04 — приемлем, если доступен только он: AWG на ядре 6.8 собирается
  без патча (условие в compat.h не срабатывает), но 22.04 — нулевой риск

## SSH не поднимается после переустановки
Сначала панель хостера: статус машины (installing/running), KVM-консоль
(systemctl status ssh, ip a), не сменились ли IP/root-пароль. Только потом —
тикет провайдеру. 07.08.2026: vdska после переустановки — ping 100% loss,
22/443 закрыты, юзер ждёт ответа провайдера.

## Исполнитель

ОС (шаг 1) делает только юзер в панели хостера.
