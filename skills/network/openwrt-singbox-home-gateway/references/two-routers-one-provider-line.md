# Раздача одной линии провайдера на 2 роутера (проверено/систематизировано 08.2026)

Вопрос пользователя: «в квартиру заходит витая пара провайдера — как раздать на 2 роутера одновременно».

## Ключевое правило (отвечать первым делом)
- PPPoE (логин/пароль — Ростелеком, Билайн и др.): ОДИН логин = ОДНА сессия.
  Два роутера с одним логином одновременно НЕ работают: второй сбросит первого (или не поднимется).
- DHCP с одним IP: аналогично — адрес один, два NAT конфликтуют. Коммутатор перед двумя
  роутерами НЕ решает (оба получат один адрес).

## Варианты (по возрастанию сложности)
1. Второй роутер как ТОЧКА ДОСТУПА (рекомендуется для «просто раздать»):
   LAN №1 → LAN №2, у №2 DHCP выключить, статический IP из подсети №1 (напр. 192.168.1.2),
   кабель в LAN-порт (не WAN). Одна общая подсеть, проброс портов один раз на №1,
   без двойного NAT. На многих моделях есть готовый режим AP в настройках.
2. «Роутер за роутером» (LAN №1 → WAN №2, двойной NAT):
   №2 остаётся роутером со своей подсетью и DHCP. Работает без настройки №2 вообще,
   но: два NAT → проблемы с играми/VPN, проброс портов нужен ДВАЖДЫ (на №1 и на №2).
   Уместен только если нужна полностью изолированная вторая сеть.
3. ДВА независимых IP / два логина от провайдера (часто платная услуга):
   витая пара → коммутатор (5-8 портов) → оба роутера WAN-портами в коммутатор.
   Каждый работает самостоятельно, свои подсети. Уточнять у провайдера заранее.
4. WISP (Wi-Fi клиент): второй роутер берёт интернет от первого ПО WI-FI как обычное
   устройство — текущая схема Cudy (см. ниже). Работает, но зависит от качества
   Wi-Fi-моста между роутерами.

## Чего НЕ делать
- Y-образный «разветвитель» витой пары 1→2 (сплиттер на 2 пары) — это для телефонии,
  ethernet (особенно гигабит) не работает.
- Два роутера в одну линию без коммутатора/режима AP — конфликт IP.

## WISP — это НЕ точка доступа
WISP = роутер принимает Wi-Fi провайдера/соседнего роутера и раздаёт дальше.
При схеме «кабель + второй роутер» он не нужен.

## Текущая домашняя схема (08.2026, работает)
- Keenetic: кабель провайдера → WAN, поднимает PPPoE, раздаёт обычный интернет БЕЗ туннелей (Keenetic-0180).
- Cudy WR3000S (сток 2.4.6 RU, 192.168.10.1, admin/VPS_ROOT_PASSWORD_PLACEHOLDER): WISP от Keenetic-0180
  (интернет по Wi-Fi от Keenetic) + WireGuard Client GeR (10.8.1.7 → 45.134.15.185:37487),
  раздаёт Cudy-B014 / Cudy-B014-5G (пароль 31122009).
- Разделение «VPN-по-выбору-Wi-Fi»: кто к Cudy — через туннель, кто к Keenetic — напрямую.
- Слабое место: Cudy держится на Wi-Fi-мостике (WISP). Улучшение: LAN Keenetic → WAN Cudy
  кабелем + в настройках Cudy переключить тип WAN с WISP на Ethernet (DHCP).
  Туннель и Wi-Fi Cudy при этом не трогаются — меняется только источник интернета.
- Проверка egress туннеля: 2ip.ru на телефоне в Wi-Fi Cudy → должен показать 45.134.15.185.
