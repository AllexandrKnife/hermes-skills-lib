# Cudy WR3000S — сброс кнопкой Reset = TFTP-режим (кейс 08.2026)

## Что случилось (таймлайн)
- Пользователь попросил «как сбросить роутер на заводские настройки».
- Агент посоветовал «зажми Reset при включении на ~10 сек» — стандартная процедура
  для большинства OpenWrt-роутеров, НО НЕ для Cudy.
- Результат: роутер ушёл в TFTP-recovery режим загрузчика: веб-интерфейс не открывается,
  горит только лампочка питания, SSH/пинг не отвечают.
- Повторные включения без кнопки не выводят из режима — роутер остаётся «кирпичом»
  до получения прошивки через TFTP.

## Корень
- Загрузчик Cudy (U-Boot) перехватывает удержание Reset при включении как сигнал
  «запустить TFTP-клиент восстановления». См. openwrt.org/toh/cudy/wr3000s_v1:
  «The Cudy bootloader will start a TFTP client for OEM recovery using the Reset button,
  but this only accepts OEM firmware.»
- Сброс настроек OpenWrt на Cudy делается ТОЛЬКО из работающей системы:
  LuCI → System → Backup/Flash Firmware → Reset, или SSH `firstboot && reboot`.

## Официальная процедура TFTP-восстановления (docs.cudy.com, извлечено 08.2026)
1. Скачать прошивку с официального сайта Cudy (или использовать промежуточный
   cudy_wr3000s-v1-sysupgrade_*.bin из /root/cudy-wr3000s-kit/firmware/), переименовать
   в recovery.bin, положить в ту же папку, что и TFTP-инструмент.
2. Выключить роутер; кабель компа → LAN-порт роутера.
3. Статический IP на компьютере: 192.168.1.88, маска 255.255.255.0, шлюз пустой.
   ПИТФОЛЛ: ставить на КАБЕЛЬНЫЙ интерфейс (Ethernet). Пользователь в кейсе выставил
   192.168.1.88 на Wi-Fi — роутер не видит. Проверка:
   powershell.exe Get-NetIPConfiguration → смотреть InterfaceAlias "Ethernet".
4. Отключить фаервол Windows: netsh advfirewall set all profiles state off (нужен админ)
   или через настройки Windows Security.
5. Запустить TFTP-инструмент от администратора (tftpd64 portable).
6. Зажать Reset на корпусе (не отпускать), включить питание. Когда TFTP начнёт
   передавать данные — отпустить Reset.
7. Ждать ~2 минуты, индикатор медленно мигает = прошивка применена.
8. Вернуть компьютеру динамический IP, проверить, что роутер восстановился.

## Ограничения и результат кейса
- Требует прав администратора Windows (статический IP + tftpd64 от админа + firewall off).
  У пользователя на ОСНОВНОМ компе прав НЕТ — НЕ блокер, а признак сменить площадку.
- РЕЗУЛЬТАТ КЕЙСА (доведено до конца 08.08.2026): восстановление УСПЕШНО выполнено
  с ДРУГОГО ноутбука (где есть права администратора), роутер вернулся на сток 2.4.6 RU.
  Рабочий паттерн: если на текущей машине нет админа — подготовить САМОДОСТАТОЧНЫЙ
  промпт для другого Hermes-агента (задача + контекст + точные шаги + критерий успеха +
  траблшутинг), пользователь запускает его на второй машине. Пример готового промпта
  сохранён в /root/cudy-recovery-prompt.txt — переиспользовать как шаблон.
- По wiki OpenWrt TFTP-режим принимает только OEM-прошивку (сток Cudy). Промежуточный
  Cudy-образ (OpenWrt-SNAPSHOT-CUDY с Cudy-magic) может пройти или нет — в кейсе не
  понадобился (использован сток с сайта Cudy).
- Альтернатива без админа: USB-UART (CH340/CP2102) + консоль U-Boot
  (tftpboot 0x46000000 cudy3000s.bin; bootm 0x46000000, TFTP на 192.168.1.88).

## Что НЕ делать
- НЕ советовать кнопку Reset как сброс настроек на Cudy — только как вход в TFTP-режим.
- НЕ перепроверять действиями то, что пользователь уже сообщил («кабель не подключён») —
  сначала уточнить.
