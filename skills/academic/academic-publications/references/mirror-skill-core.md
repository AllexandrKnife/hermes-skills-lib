# Паттерн ядра скилов-зеркал (eko-core, 15.08.2026)

Как превратить набор компетенций исследователя (или любого профиля)
в локальное ядро переиспользуемых скилов с проверяемыми кейсами.
Реализация: /root/eko-core (27 скилов, зеркало профиля Устинова А.Э.).

## Структура

```
core/
  <domain>/
    <skill-name>/
      SKILL.md          # процедура (см. ниже)
      case_<skill>.py   # прогон кейса, завершается печатью CASE_OK
  references/
    template_SKILL.md   # шаблон каркаса
    gen_card.py         # автогенератор каркаса из шаблона
    verify_core.py      # CI: запускает все case_*.py, PASS/FAIL
    data/               # датасеты кейсов
```

## Формат SKILL.md (каждый скил)

frontmatter: name, description «Use when ...» (<=60 симв.), version,
critic_status, category, mirrors (какую компетенцию зеркалит).

Секции: Когда использовать / Входные данные / Шаги / Инструмент
(мини-код) / Выход / Проверка (верификация) / Pitfalls / Кейс (зеркало).

## verify_core.py (CI-приёмка)

- Ищет все case_*.py в доменах, запускает каждый (timeout 120),
  PASS = exit 0 и в stdout есть 'CASE_OK'.
- Скил «принят», только если его кейс зелёный. Прогон обязателен
  до critic_status: done.

## Ключевые принципы

1. **Зеркало метода, не копия цифр**: кейс воспроизводит методологию
   статьи на актуальных/своих данных. Расхождение с публикацией
   (иной период, набор факторов) — документировать в кейсе и SKILL.md
   («урок: результат зависит от данных»). Не подгонять под публикацию.
2. **Кейс из текста**: для действующих компетенций — извлечь процедуру
   из статьи автора (таблицы статей — готовые референсные данные:
   воспроизводить расчёт по ним, проверяя выводы статьи).
3. **Честный результат**: незначимый/«плохой» результат — валидный
   результат (DiD p=0.41, ML без прироста на малой выборке) —
   фиксировать с причиной, а не подбирать параметры до «зелёного».
4. **Критика перед done**: reviewer.py --triz на SKILL.md (exit 0),
   потом critic_status: done. Без прогона кейса — не принимается.
5. **Инфраструктура экономит**: gen_card.py создаёт каркас за секунды,
   verify_core.py — один прогон всех кейсов.

## Порядок сборки ядра

День 0: окружение (pandas/statsmodels/sklearn/matplotlib — версии в
requirements), структура, шаблон+генератор, verify_core, данные.
Трек A (MVP, 6-8 скилов на готовых данных) -> трек B (панели/каузальность)
-> трек C (процедурные по текстам) -> трек D (новые методы: ML, NLP).
Порядок скилов — по доступности данных (ТРИЗ приём 13 «наоборот»),
новые методы — через репликацию известных моделей (приём 26).

## Типовые ошибки (pitfalls)

- os.replace между /tmp и диском: OSError cross-device — использовать
  shutil.move.
- numpy 2.x: np.npv/np.irr удалены — ручная формула дисконтирования
  или scipy.optimize.brentq.
- pandas: df[cols].join(dummies) -> object dtype, OLS падает
  «cast to numpy dtype of object» — явно .astype(float).
- Панель 10 стран x 23 года (230 строк) — ML не даёт прироста над OLS;
  сравнивать честно, пометить ограничение выборки.
