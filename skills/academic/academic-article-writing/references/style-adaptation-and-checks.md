# Стилизация статей под автора + проверки перед выдачей

Проверено 15.08.2026: 5 статей серии (ипотека DiD, Монте-Карло, Tobin Q,
ML-инновации, IT-парадокс) адаптированы под стиль Устинова А.Э. и проверены
на артефакты ИИ + антиплагиат. Дополняет SKILL.md (этапы 9-10 конвейера).

## Анализ стиля автора (по корпусу его статей)

Взять 2-3 полных текста (Статьи_txt) и извлечь:
- заголовки разделов: «Введение» / «Заключение» — БЕЗ номеров, БЕЗ капса,
  БЕЗ рамок (никаких «1. ВВЕДЕНИЕ» и ====);
- «ИСТОЧНИКИ:» вместо «СПИСОК ЛИТЕРАТУРЫ» (в свежих статьях);
- англ. блок: ABSTRACT + KEYWORDS + JEL — сразу после русской аннотации
  (в русском блоке: название, авторы, аннотация сплошным текстом,
  «Ключевые слова:», JEL);
- фирменная концовка аннотации: «Статья ориентирована на представителей
  научного сообщества и, имея практическую значимость и актуальность, будет
  интересна представителям бизнеса...»;
- обороты: «на наш взгляд», «представляется целесообразным», «целесообразно»,
  «Таким образом» — умеренно (1-2 на статью);
- титул: ФИО / к.э.н., должность / институт / университет / ORCID — 4-5 строк
  без пустых.

## Механика адаптации (порядок)

1. Заголовки: regex-замена «N. НАЗВАНИЕ» в рамках ==== → «Название»
   (6 разделов + «ИСТОЧНИКИ:»). Рамки вокруг ИСТОЧНИКИ убирать ОТДЕЛЬНО
   (replace слова рамки не трогает).
2. Англ. блок: вставка после строки «JEL: ...» (перевод аннотации 5-8
   предложений + KEYWORDS).
3. Фирменная фраза — перед «Ключевые слова:»; в СЕРИИ статей ВАРЬИРОВАТЬ
   формулировку (одинаковая = 13 окон пересечения между парами в
   антиплагиате, хотя для одного автора это легитимно).
4. «На наш взгляд» — в ПЕРВЫЙ АБЗАЦ раздела «Обсуждение», НЕ перед первым
   подзаголовком («На наш взгляд, 5.1. Идентификация...» — баг).
5. Вставки делать ДО финальной выключки; после вставок не гонять полный
   justify — только затронутые абзацы (иначе титул склеивается).

## Питфоллы (найдены в сессии)

- Полный justify после вставок склеивает титульный блок
  («Устинов Артур Эдуардович к.э.н., доцент...» — одна строка). Решение:
  титул в skip-списке форматтера.
- `KEYWORDS:` с текстом — startswith, не точное равенство: при точном
  равенстве строка уходит в абзац и слипается с последним абзацем ABSTRACT.
- Замены по одинарному пробелу не находят строки с двойными пробелами
  растяжки: «Ключевые  слова:» — replace молча не срабатывает. Искать по
  нормализованному (re.sub(r'\s+', ' ', t)).
- Фраза, разбитая ПЕРЕНОСОМ строки, не находится regex по одной строке —
  искать по всему тексту с \s+ (матчит \n).

## Проверки перед выдачей

### Артефакты ИИ (scripts/check_ai_tells.py)
- Англ. AI-слова в ABSTRACT (additionally, crucial, pivotal, underscore,
  showcase, seamless...), -ing-хвосты, русский канцелярит (ru-markers из
  humanizer), эм-даши/1000 симв (норма 1-3 — русская типографика),
  правило трёх, «данный» как указательное, «но и» с границами слов.
- КРИТЕРИЙ: единичные канцеляритные обороты («в свою очередь», «таким
  образом», «в целом», «не только... но и») — НОРМА научного стиля, НЕ
  артефакт. Артефакт = злоупотребление (многократные повторы) или англ.
  AI-словарь. Фирменные обороты автора («на наш взгляд», «целесообразно»)
  — намеренная стилизация, не артефакт.

### Антиплагиат локально (scripts/antiplagiat_shingles.py)
- Шинглы 10 слов: self-дубли (уникальность окон 99-100% — норма),
  пересечения между статьями серии (1-5%), совпадения с корпусом автора
  (обычно <2% — ФИО + библиография).
- Легитимные пересечения: титульный блок, фирменная фраза, библиография
  (общие источники: РБК/ЦБ/статьи автора), общие рыночные факты
  (пересказ). Реального плагиата нет, если совпадения только эти.
- Ограничение: веб-проверка (совпадения с интернетом) без сервиса
  антиплагиата невозможна; по построению текст — пересказ фактов с
  указанием источников, не копия.
